# v0.4 收敛期设计：主线修稳 + 助手降级重建 + 真实验收

日期：2026-07-08。批准人：luke。执行方：Claude（手术）+ Codex 子代理（按卡收尾，过审核门）。

## 0. 背景与问题

v0.3 期间 Codex 无监督连跑数日，主线 11 页中 9 页达到 Verified，但 Agent 模块失控膨胀：
`agent.dart` 19,965 行 + 相关文件共 **25,671 行**，内含手写 JS 表达式解释器（~8k 行）、
ES 风格查询 DSL（~4k 行）、多层子 Agent 监督编排（~2.5k 行）、10 张手抄参数别名表
（241 处重复，~1.25k 行）。对照：整条视频生产主线引擎合计约 1.4 万行。
两轮对抗式审查共确认 **20 个真实 bug**，账目：砍除直接消灭 10（解释器 8 + 监督 2），
向量路径删除消灭 1，入口路由设计消灭 1，归一化函数替代解决 1，**剩 7 个真修**
（C2 修 2、C3 修 5，见 §5/§6）。

结论（luke 与 Codex 复核一致）：Agent 应是"短剧制作助理"，不是
"搜索引擎 + 编程语言解释器 + 多智能体平台"。

## 1. 目标与非目标

**目标**：
1. 助手降级重建：砍到"对话式流水线助理"水位，文件边界清晰、命名去 Agent 平台化。
2. 确认闸下沉：花钱/破坏动作的确认统一在流水线入队层，覆盖一切入口（UI 按钮与助手同闸）。
3. 主线修稳：修复 8 个存活 bug，时间线单/批量操作收拢为单一排布引擎。
4. 真实验收：真实供应商全链路（azt 文本图片 + Seedance 视频），Mac 由 luke 亲手走通，
   iPhone 模拟器同流程复验。

**非目标（本期明确不做）**：
- 零新功能（唯一例外：确认闸，它是被砍监督门的替代品）。
- 不做 Web/H5（M6 单独立项，另写设计）。
- 不重新设计主线模块（项目/小说/事件/剧本/资产/分镜/视频/配音/合成结构不动）。
- 不做向量 RAG、不做自定义 JS 技能执行、不做多层子 Agent。

## 3. 新增横切层：pipeline_policy（确认闸，唯一新概念）

文件：`app/lib/src/engine/pipeline_policy.dart`

- 按 taskClass 声明元数据：`costsMoney`（asset_image_generation、storyboard_image_generation、
  video_generation、tts_generation、以及批量 LLM 生成类）、`destructive`
  （删资产/覆写剧本/清笔记/清数据等）。
- 判定函数：`PolicyDecision checkAction(taskClass, {mode})` → `allow | needsConfirm(提示文案)`。
- **所有入口统一过闸**：UI 按钮与助手动作在入队/执行前调用判定；需要确认时由 UI 弹窗，
  确认后放行。引擎层只判定与放行，不做 UI。
- 默认策略：manual 模式下花钱+破坏均确认（花钱的展示"本次将调用 N 次生成"）；
  auto 模式下花钱放行但发一条可见通知，破坏仍确认。
- 全局开关（o_setting 键 `policy.confirmEnabled` 等），提示文案全部走 l10n（zh/en/ja）。

## 5. 时间线排布引擎（主线唯一结构性修复）

文件：`app/lib/src/engine/timeline_clip.dart`（内部重构，公开 API 不变）

抽单一核心：`_placeClips(scriptId, placements, {PlacementMode mode})`，
mode ∈ {splitOverlap（分割让位）, ripple（波纹位移）, clamp（钳制）}。
单个与批量操作全部改为薄封装调它。修复并锁死：

| 存活 bug | 修法 |
|---|---|
| moveTimelineClipsRipple 缺分割让位（产生真实重叠） | 走排布引擎 splitOverlap 路径 |
| resizeTimelineClipsEndRipple 位移重复累加 + 选中互相重叠 | 引擎内一次性计算净位移 |
| workbench `_splitSelectedClipsAtPlayhead` 丢弃新尾段选中 | 返回新 ID 并入 `_selectedClipIds` |
| workbench 批量裁剪未排除同批选中（互当障碍物） | 统一走 `ignoredClipIds` 模式 |
| 82a2839 N+1 回退 | 还原批量 SQL；引擎按"每操作一次读+一次批量写"设计 |
| 拖拽手势多次全表查询 | 每手势快照一次，吸附/避让复用快照 |

**等价性测试**（新增，防复发核心）：对 {move, duplicate, delete, resizeEnd} ×
{ripple, 非 ripple}，断言"批量传单个 ≡ 单个方法"的落库结果完全一致。
