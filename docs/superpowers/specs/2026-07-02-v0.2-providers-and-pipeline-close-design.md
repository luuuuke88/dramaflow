# DramaFlow v0.2 设计：配置后台 + 成片闭环（M1-M4）

> 2026-07-02。前置：v0.1 已验证（显式流水线后端 + Flutter 客户端，文本/图片链路实测通过）。
> 本轮决策记录：底座=演进 DramaFlow（不换 ToonFlow 后端）；供应商体系=方案B（协议适配器+声明式配置，不用 vm2 脚本沙箱）；账号系统本轮不做（数据层预留 userId，配置导出/导入作为手动同步替代）；媒体文件全部本地；商业化/自有 API 服务后置（届时作为 openai_compatible 的一个实例接入，零代码）。

## 目标

对照 ToonFlow 补齐四块能力，按 M1→M4 顺序交付，每个里程碑独立可用、独立验收：

1. **M1 供应商可插拔后台**——界面里添加/管理任意供应商，7 个流水线环节各自绑定模型，提示词可编辑
2. **M2 成片闭环**——镜头视频多版本选片 → ffmpeg 拼接 → 导出整集 mp4
3. **M3 图片重绘**——基于当前图+修改意见重绘，图片版本化可回退
4. **M4 配音**——角色声音绑定、逐镜台词 TTS、合成时混音

## M1 供应商可插拔后台

### 数据模型（新增表）

```sql
providers (
  id TEXT PK, name TEXT, protocol TEXT CHECK(protocol IN ('openai_compatible','volcengine')),
  baseUrl TEXT, apiKey TEXT, enabled INTEGER DEFAULT 1,
  userId TEXT DEFAULT '',          -- 账号系统预留
  createdAt TEXT
)
provider_models (
  id TEXT PK, providerId TEXT FK ON DELETE CASCADE,
  modelId TEXT,                    -- 传给上游的真实模型名
  label TEXT,                      -- 界面显示名
  kind TEXT CHECK(kind IN ('text','image','video','tts')),
  capabilities TEXT DEFAULT '{}',  -- JSON: 视频{durations,resolutions,audio}; 图片{modes}
  enabled INTEGER DEFAULT 1
)
prompts (
  key TEXT PK,                     -- script_gen_system / asset_extract_system / storyboard_gen_system / repair_wrapper / image_size_directive
  content TEXT,                    -- 当前生效内容
  updatedAt TEXT
)
```

- **环节绑定**存 settings 表：`binding.<stage>` = `"providerId:modelId"`。七个 stage：`script_gen, asset_extract, storyboard_gen, asset_image, shot_image, shot_video, tts`（tts M4 启用）。
- 迁移：首次启动 seed 两个内置 provider 实例（azt = openai_compatible 指向 127.0.0.1:8787；volcengine 带现有 key），模型与当前 settings 等价，绑定自动指向它们——**升级后行为与 v0.1 完全一致**，旧 settings 的 text*/image*/video* 键废弃但保留读取兜底一个版本。

### 协议适配器（后端代码，非脚本）

```
server/src/providers/
  types.ts        -- ProviderAdapter 接口: generateText / generateImage(prompt, refs?) / generateVideo / generateTts
  openaiCompat.ts -- chat/completions + images/generations + images/edits + audio/speech
  volcengine.ts   -- 现有实现改造成适配器（文本/seedream图片/seedance视频/TTS）
  resolve.ts      -- stage → binding → (adapter实例, modelId)；所有 runner 改为经 resolve 取模型
```

约束：适配器内不做计费/日志（钩子留在 resolve 层，对应未来计量需求）。azt 的已知行为（长 header 等待 960s、尺寸指令注入）保留在 openaiCompat 中，尺寸指令改为从 prompts 表读。

### 提示词管理

- runners 改为从 prompts 表读（启动 seed 内置默认值，代码里的常量作为"重置"来源）。
- API：`GET /api/prompts`、`PUT /api/prompts/:key`、`POST /api/prompts/:key/reset`。

### API（新增/调整）

- `GET/POST /api/providers`、`PATCH/DELETE /api/providers/:id`（apiKey 打码规则沿用 settings 的 `****` 约定）
- `POST /api/providers/:id/test`——用一条最小请求实测该 provider 的指定模型（text: "只回复OK"；image/video 只校验鉴权不真生成）
- `GET/PUT /api/providers/:id/models`（整表替换式保存）
- `GET /api/bindings`、`PUT /api/bindings`（body: `{stage: "providerId:modelId", ...}` 子集）
- `GET /api/config/export` → 单 JSON（providers 含明文 key + bindings + prompts，**含密钥，提示用户妥善保存**）；`POST /api/config/import`（同构 JSON，冲突策略：同名 provider 覆盖）

### Flutter 设置页改版

三个板块（宽屏左右分栏，窄屏 tab）：**供应商**（列表+新建/编辑/测试连通，模型子列表编辑）、**模型绑定**（7 个环节各一行下拉，选项来自对应 kind 的启用模型）、**提示词**（列表+编辑器+重置按钮）。连接设置（后端地址/token）保留在页首。导出/导入配置入口在页尾。

### 验收

界面添加一个新的 openai_compatible 供应商指到 azt → 把 script_gen 绑到它 → 生成剧本成功；编辑分镜提示词（如改镜头数上限）→ 重新生成分镜可见生效；导出配置删库重导入后一切照旧。

## M2 成片闭环

### 数据模型

```sql
video_takes (
  id TEXT PK, shotId TEXT FK ON DELETE CASCADE,
  videoPath TEXT, durationSec REAL,       -- ffprobe 实测
  createdAt TEXT
)
-- shots 表: videoPath/videoStatus 保留（=当前选中 take 的冗余），新增 selectedTakeId TEXT
episodes 表新增: composedPath TEXT, composeStatus TEXT DEFAULT 'none', composeError TEXT
```

- shot_video job 完成时写入 video_takes 新行并自动选中（旧行为不变，多次生成=多版本）。
- v0.1 已有的 videoPath 迁移为第一条 take。

### 合成

- 新 job kind `compose`（video 车道）：按 idx 顺序取每镜选中 take → ffmpeg concat（统一转 720p/30fps/h264+aac，避免不同 take 参数不齐导致拼接失败）→ 输出 `media/<projectId>/ep_<episodeId>_<ts>.mp4`。
- ffmpeg 来源：优先系统 PATH，检测不到时 health 与合成按钮提示安装命令（`brew install ffmpeg`），不内置二进制。
- 前置校验：本集所有镜头都有选中 take，否则 400 列出缺失镜头号。

### API 与 UI

- `GET /api/shots/:id/takes`、`POST /api/shots/:id/select-take`（body: takeId）
- `POST /api/episodes/:id/compose` → `{jobId}`；episodes 列表/详情返回 composeStatus/composedPath
- 分镜页：镜头卡的视频区变成 take 横滑列表（选中高亮，点击切换，可内联播放——引入 video_player，桌面端 fallback 复制链接）；集页新增「合成本集」按钮 + 成片卡（播放/在 Finder 显示/复制路径）。

### 验收

一集 8 镜各有 ≥1 个 take → 合成 → 得到可播放 mp4，时长≈各镜之和；某镜生成第二个 take 并切换选中 → 重新合成产物变化。

## M3 图片重绘

- openaiCompat 适配器补 `images/edits`（azt 已支持该端点）；volcengine 用 seedream 参考图模式。适配器接口统一为 `generateImage(prompt, refImagePaths?)`。
- 图片版本化：与 M2 同构的 `image_takes` 表（assetId/shotId 二选一外键 + imagePath + selected）。资产/镜头图生成改写为新增 take。
- 重绘交互：图片详情弹窗加「重绘」——输入修改意见，后端把 `当前图 + 原提示词 + 修改意见` 交给绑定的 image 模型（走 edits 端点），产出新 take。
- Job kind 复用 `asset_image`/`shot_image`（payload 加 `refTakeId` 与 `editInstruction`）。
- 验收：对一张素材图输入"改成红色衣服"→ 得到新版本，可在版本列表切换/回退。

## M4 配音

- 适配器补 `generateTts(text, voice)`：openai_compatible 走 `/audio/speech`；volcengine 走豆包 TTS。
- 数据：assets(kind='character') 新增 `voiceId TEXT`；shots 新增 `audioPath/audioStatus/audioError`；job kind `shot_tts`（新 lane `tts`，并发 2）。
- 流程：设置页绑定环节模型 → 素材库角色卡选声音（provider_models kind='tts' 的 capabilities.voices）→ 分镜页「生成配音」逐镜把 dialogue 转音频 → M2 合成时若镜头有 audioPath 则 ffmpeg 混入（对白轨覆盖在原生成音轨上，音量 ducking 简单处理：原轨 -12dB）。
- 无台词镜头跳过。验收：两镜有台词的集合成后能听到对白。

## 全局约定

- 错误处理沿用 v0.1：一切失败落库带原因、可重试；新增 job kind 全部进现有队列/恢复机制。
- 每个 M 结束：`tsc --noEmit` + `flutter analyze` 零告警、真实 E2E 一条、并行 code review + 修复、git 提交。
- 不做的事（YAGNI）：账号/云同步、计费计量、Windows/iOS 打包、ToonFlow 的 Agent 对话模式、事件抽取粒度细化（现有小说→剧本粒度目前够用，观察后再议）。
