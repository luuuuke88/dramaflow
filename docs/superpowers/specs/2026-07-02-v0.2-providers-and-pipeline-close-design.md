> 首版 2026-07-02，修订 2026-07-03。
>
> **决策记录**
> - 2026-07-02：底座=演进 DramaFlow；供应商体系=方案B（协议适配器+声明式配置，不用脚本沙箱）；账号本轮不做（预留 userId+配置导出导入）；媒体全本地；商业化/自有 API 后置（届时=一个 openai_compatible 实例）。
> - 2026-07-02 深夜：UI 反馈——v0.1 深色卡片流"乱、没有章法"，改为**模仿 ToonFlow 信息架构**（白底表格化），自由设计留到功能站稳后。
> - 2026-07-03：**架构转向（最重大）**——目标形态是可上架 Mac/iOS/iPad/Android 的**独立 App**，重计算（合成等）在端上。因此 Node 后端退役，引擎用 Dart 重写内嵌进 Flutter App；v0.1 的 schema/提示词/流水线设计 1:1 移植，Flutter 界面与 ApiClient 门面保留。

## 目标形态

单一 Flutter App（macOS / iOS / iPad / Android；Windows 后置；Web 构建降级为开发预览不保证功能），内含：Dart 引擎（数据库+任务队列+AI调用+合成）、全部数据与媒体在设备本地、AI 供应商界面可配置、无需任何伴随进程。

交付顺序（每个里程碑独立可用、独立验收）：

| 里程碑 | 内容 |
|---|---|
| **M0 引擎内嵌** | Node 后端逻辑 → Dart in-app 引擎，App 单体可用 |
| **M1 UI 重构** | 对标 ToonFlow：浅色主题、表格化管理、批量/搜索/分页、道具类型、分镜时间线看板 |
| **M2 配置后台** | 供应商可插拔 + 环节模型绑定 + 提示词管理 + 配置导出导入 |
| **M3 成片闭环** | 镜头视频多版本选片 → 端上 ffmpeg 拼接 → 导出整集 mp4 |
| **M3.5 自动连跑** | 双模式：分步（现状）/ 自动（一键从小说到成片，出错即停可续跑） |
| **M4 图片重绘** | 参考当前图+修改意见重绘，图片版本化 |
| **M5 配音** | 角色声音绑定、台词 TTS、合成混音 |

**M0 的引擎设计必须为 M3.5 预留**：job 完成回调可触发后继阶段（导演循环的钩子），避免自动模式成为事后补丁。

## M0 引擎内嵌（Dart in-app engine）

### 结构

```
app/lib/src/engine/
  db/            -- drift 定义（表结构 = v0.1 server schema 平移：projects/novels/episodes/
                    assets/shots/jobs/settings + 后续里程碑新表；全表带 userId TEXT DEFAULT ''）
  queue.dart     -- 任务队列（车道串行：text=1/image=1/video=1，启动恢复 running→failed，
                    逻辑照抄 v0.1 queue.ts）
  providers/     -- ProviderAdapter 抽象 + openai_compat.dart + volcengine.dart
                    （dio 实现；azt 长等待 960s 超时、尺寸指令注入等已知行为保留）
  pipeline/      -- prompts.dart + runners.dart（结构化输出 zod→手写校验+自愈重试一次，
                    错误全部落库带原因，照抄 v0.1 语义）
  engine.dart    -- 门面：方法签名 = 现 ApiClient 的方法集（listProjects/generateScript/...），
                    界面层零改动接入
  media.dart     -- 媒体文件管理（App documents 目录，图片/视频读写与清理）
```

- **界面接入**：`apiProvider` 换成 `engineProvider`；`MediaImage` 从 Image.network 改为 Image.file；活跃任务轮询改为引擎内直接 watch（Stream，比 HTTP 轮询更实时，activeJobsProvider 对外接口不变）。
- **依赖**：drift（SQLite）、dio、path_provider、wakelock_plus（生成期间保持屏幕常亮，对策 iOS 后台冻结）。
- **Node 后端处置**：`server/` 保留在仓库作参照与应急（README 标注 deprecated），不再开发。
- **数据迁移**：提供一次性导入（macOS 上选择 v0.1 的 `server/data` 目录 → 拷贝 sqlite 数据与 media 文件）；仅 macOS 提供，属 P2（测试数据可重新生成，不阻塞）。
- **已知约束（记录进 README）**：iOS/Android 长任务依赖前台+屏幕常亮，锁屏可能中断（任务会按失败落库可重试）；Web 构建不支持本地引擎的文件能力，仅作 UI 预览。

### M0 边界约定（2026-07-03 外部审计后补充）

**1. Provider Reality（供应商现实约束）**
- macOS 上 azt/127.0.0.1 仅作为**开发供应商**存在；Android/iOS 无伴随进程，**必须**使用真实远程 API 供应商。
- seed 策略按平台分化：macOS seed azt+volcengine 两实例；移动端首启只 seed volcengine（用户填 key）并引导配置。
- **M0 Android 验收不得依赖宿主机 localhost**：文本绑 volcengine doubao、图片绑 volcengine seedream（现有 key 可用），跑通即验收。"不用 API Key、不跑伴随进程、还要移动端生成"三者不可兼得，移动端取"真实 API Key 直连"。

**2. UI Compatibility（界面兼容的诚实口径）**
- 承诺缩小为：**业务方法形状兼容**（listProjects/generateScript/... 的签名与语义不变）。
- 明确允许改动的三处：媒体展示（mediaUrl→本地文件路径，MediaImage 改 Image.file）、任务状态源（HTTP 轮询→引擎内 Stream，activeJobsProvider 内部重写）、错误类型（ApiException→EngineException，message 语义不变）。按"小范围 UI 适配"估工，不按零改动。

**3. Engine Lifecycle（Flutter 内嵌队列的生命周期）**
- Engine 为 **App 级单例**（main() 初始化，不挂在任何可重建的 Provider 上；Riverpod 只持有它的引用）。
- Queue.start() **幂等**（重复调用无副作用，全局唯一 worker loop；热重载不会叠加 worker）。
- App 启动时执行恢复：`running → failed('应用重启，任务中断')`；**resume（从后台回前台）不触发恢复**，只有冷启动触发（后台冻结期间任务可能仍在收尾）。
- Provider/widget 的 dispose 与任务执行完全解耦：任务由 Engine 持有，界面销毁不取消任务。
- 取消语义：queued 可取消；running 允许用户手动取消（dio CancelToken 中断请求，任务标 canceled）——移动端长任务尤其需要这个出口。
- 长任务护航：存在活跃任务时 wakelock 常亮 + 状态栏提示；系统仍杀掉请求时按失败落库可重试。

**4. Schema 策略**
- M0 一次性建**全量 schema**（含本文档 M1-M5 已定的全部表和字段：prop kind、note、providers/provider_models/prompts、video_takes/image_takes、voiceId/audioPath 等），schemaVersion=1。
- 后续里程碑原则上不动表结构；确需变更时走 drift schemaVersion 迁移，禁止 ad-hoc ALTER。

### 验收

- macOS：无任何本地服务（azt 可作为供应商配置存在但验收用例不依赖它）→ 新建项目→导入小说→生成剧本→提取素材→生成 1 张素材图。
- Android（模拟器或真机）：绑定 volcengine 文本+图片模型，同一流程走通，全程不依赖宿主机 localhost。
- 双端：杀 App 冷启动后数据完好、中断任务标失败可重试；运行中任务手动取消生效。

## M1 UI 重构（对标 ToonFlow）

- **主题**：浅色默认（白底、蓝主操作色、灰阶分隔，参照 ToonFlow 观感），Material 3 双主题，暗色留为设置项。
- **素材页**（对标 ToonFlow 资产页）：顶部 tab **角色/道具/场景**（assets.kind 新增 'prop'，提取提示词补道具规则）；宽屏表格化列表（缩略图/名称/提示词截断/描述截断/备注/操作），行首复选框、行可展开；工具栏：新增、批量生成、批量删除、搜索；底部分页（10/20/50）；窄屏退化紧凑卡片。assets 新增 `note` 字段。
- **分镜页**做成时间线看板式：镜头有序排列（宽屏横向卡片流/窄屏纵向列表）、**拖拽调序、插入/删除镜头**、每镜缩略图+状态+操作——覆盖节点画布在短剧工作流中的主要用途（排镜、调序），成本远低于画布；**流水线总览**保留但视觉减重（白底分区、细边框）。
- **全局**：左侧图标导航保留，页面统一"标题栏+工具栏+内容区"三段式。
- **验收**：1280px 下素材页与 ToonFlow 布局逐项对齐（tab/表格/批量/搜索/分页）；375px 可正常操作；道具类型走完提取→生图。

## M2 配置后台（供应商可插拔）

数据（drift 表）：

```
providers        (id, name, protocol['openai_compatible'|'volcengine'], baseUrl, apiKey, enabled, userId, createdAt)
provider_models  (id, providerId, modelId, label, kind['text'|'image'|'video'|'tts'], capabilities JSON, enabled)
prompts          (key PK, content, updatedAt)   -- 内置默认值 seed，可改可重置
```

- **环节绑定**：settings 键 `binding.<stage>` = `providerId:modelId`；stage = script_gen/asset_extract/storyboard_gen/asset_image/shot_image/shot_video/tts。runners 全部经 `resolve(stage)` 取适配器+模型。
- **首次升级 seed**：azt（openai_compatible→127.0.0.1:8787）+ volcengine 两实例与现有模型，绑定自动对齐——升级后行为与之前一致。
- **引擎方法**：providers CRUD + testProvider（text 发"只回复OK"，image/video 仅校验鉴权）+ models 整表保存 + bindings 读写 + prompts 读写/重置 + 配置导出/导入（单 JSON 含明文密钥，导出时提示妥善保管；同名 provider 覆盖）。
- **设置页**：供应商 / 模型绑定（7 环节下拉）/ 提示词 三板块 + 导出导入入口。
- **验收**：界面新增一个指向 azt 的供应商→绑定 script_gen→生成剧本成功；改分镜提示词→重新生成可见生效；导出→清数据→导入→一切照旧。

## M3 成片闭环

- **合成在端上**：`ffmpeg_kit_flutter_new`（原 ffmpeg-kit 的社区维护版，LGPL 配置，支持 iOS/Android/macOS）。Windows 版后置（届时打包 ffmpeg.exe 资源）。
- 数据：`video_takes (id, shotId, videoPath, durationSec, createdAt)`；shots 加 selectedTakeId；episodes 加 composedPath/composeStatus/composeError。shot_video 完成=新增 take 并自动选中；v0.1 旧 videoPath 迁为首条 take。
- compose job（video 车道）：按镜头顺序取选中 take → 统一转 720p/30fps/h264+aac → concat → 输出到媒体目录。前置校验齐镜，缺则报缺失镜头号。
- UI：镜头卡视频区= take 横滑列表（选中高亮、内联播放 video_player）；集页「合成本集」+ 成片卡（播放/分享/导出到相册或 Finder）。
- **验收**：8 镜各≥1 take → 合成得到可播放 mp4（时长≈各镜之和）；换选 take 重合成产物变化。macOS 与 Android 双端验收。

## M3.5 自动连跑（双模式）

- **产品形态**：项目页顶部模式切换——「分步模式」（现状，每步手动触发）/「自动模式」（选定范围后一键开始，引擎自动串联 剧本→素材→素材图→分镜→镜头图→视频→合成 直到成片）。
- **引擎实现**：导演循环（director）——监听 job 完成事件，按流水线拓扑自动入队下一阶段；范围可选"仅本集"或"全部集"。
- **出错即停**：任一 job 失败则自动模式暂停在该阶段（不回滚、不跳过），界面提示失败原因；用户修复/重试后可「继续自动跑」。不承诺无人值守成功率，承诺"自动推进+可续跑"。
- **可中断**：自动模式随时可暂停/退出回分步模式，状态不丢（一切以 DB 为准）。
- **验收**：一部小说在自动模式下从零跑到某一集成片 mp4，途中人为制造一次失败（断网），验证停在原地、恢复后续跑到完成。

## M4 图片重绘

- openai_compat 适配器补 images/edits（azt 已支持）；volcengine 走 seedream 参考图。适配器统一 `generateImage(prompt, {refImagePaths})`。
- `image_takes` 表（assetId/shotId 二选一 + imagePath + selected），素材图/镜头图生成一律新增 take。
- 交互：图片详情加「重绘」——输入修改意见，引擎以 `当前图+原提示词+修改意见` 走 edits，产出新 take；版本列表可切换回退。
- **验收**：对素材图输入"改成红色衣服"→新版本生成且可回退。

## M5 配音

- 适配器补 `generateTts(text, voice)`（openai_compatible→/audio/speech；volcengine→豆包 TTS）。
- 角色 assets 加 voiceId；shots 加 audioPath/audioStatus/audioError；job kind shot_tts（tts 车道，并发 2）。
- 流程：绑定 tts 模型→角色卡选声音→分镜页逐镜生成配音→合成时 ffmpeg 混音（原轨 -12dB，无台词镜头跳过）。
- **验收**：两镜有台词的集，成片能听到对白。

## 全局约定

- 错误处理沿用 v0.1 语义：一切失败落库带原因、可重试；新 job kind 全部进统一队列与启动恢复机制。
- 每个 M 收尾：`flutter analyze` 零告警 + 真实 E2E 一条 + 并行 code review 修复 + git 提交；涉及生成的用 azt/Codex token 自测，视频类留真机验证点给用户。
- 不做（YAGNI）：账号/云同步、计费、ToonFlow 对话式 Agent、事件抽取粒度细化、Windows 打包。
