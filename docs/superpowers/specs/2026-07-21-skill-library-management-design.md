# 技能库文件管理设计

## 背景与边界

本批次只恢复 ToonFlow 1.1.8 中用户实际可使用的 Markdown 技能文件管理：
浏览、搜索、预览、编辑、保存、启停，以及一次可靠的“重扫”。原版 Web 的
`scanSkills` 按钮会调用一个 1.1.8 后端不存在的 HTTP 路由，因此不复制其伪进度。

本批次不恢复自定义 JavaScript 技能执行、子 Agent 编排、向量检索或按需激活协议。
它们属于后续 W2 Agent 批次，不能借文件管理之名偷偷扩大范围。

## 决策

### 应用拥有技能工作区

每个安装使用数据目录下的 `skills/` 是唯一受管理根目录。导入 `.md` 或包含
`SKILL.md` 的目录时，内容复制进该根目录，再由 SQLite 的 `o_skillList.path` 指向
应用内文件。不得继续把用户选取的外部绝对路径作为长期依赖：移动端权限、文件被移动和
桌面外接盘都会让那种做法失效。

已有指向外部路径的 Markdown 行，在首次扫描时只报告为“丢失”，不静默删除，也不读取
根目录外内容。用户可以重新导入。所有根目录内路径必须拒绝绝对路径、`..` 和符号链接
逃逸。导入源是用户经系统文件选择器明确授予的一次性文件路径，可以是绝对路径；应用只
读取并复制它，绝不把该源路径写入数据库作为后续依赖。

### 扫描的可观察语义

扫描递归枚举应用 `skills/<id>/SKILL.md` 入口文件，解析 frontmatter，并按稳定技能 ID
将数据库与磁盘对账：新增文件建记录，正文或元数据变更更新记录，消失的应用内文件标记
为不可用但保留记录。包内其它 Markdown 是可读取资源，不能被误注册为技能。结果返回新增、
更新、丢失、无效 frontmatter 的精确数量和条目，供 UI 展示。它不进行任何模型、图片或视频调用。

### 跨端界面

Agent 的“技能”页成为文件管理器：顶部提供导入、重扫和搜索；列表展示 Markdown 技能
及内置动作；选中 Markdown 项后可预览、编辑、保存、启停。桌面使用双栏列表和详情；
窄屏使用列表到全屏详情的单栏导航。两端采用同一引擎 API、同一内容与同一启停语义。

本批文件选择使用现有 `file_selector`，桌面与移动端都只提供单个 `.md` 导入。桌面选择
包含 `SKILL.md` 的目录需要单独验证文件选择器的跨平台支持，留作后续增量；导入
`SKILL.md` 时仍会复制其同目录的常规资源。任何后续目录导入都只能复制 Markdown 和同目录
资源，且不可覆盖根目录外内容。

## 接口边界

新增独立 `assistant_skill_library.dart`，负责受限文件系统和扫描结果；
`assistant_skills.dart` 保留数据库行、frontmatter 解析、启停和当前提示词上下文接口。
UI 不直接读写文件。技能根目录由既有 `media.rootDir` 的同级运行数据目录推导：
`Engine.boot(dataDir:)` 已把媒体根设为 `dataDir/media`，而直接构造的测试引擎也用同一
规则落到临时目录。这样无需扩大 `Engine` 构造器接口。

## 验收

- 引擎测试：导入复制、同 ID 更新、扫描新增/更新/丢失、越界路径/符号链接拒绝、无效
  frontmatter 统计、启停持久化。
- Widget 测试：桌面和 390dp 都可导入、搜索、预览、编辑保存、重扫并看到统计；文本不
  发生溢出，移动端详情可返回列表。
- 所有验证使用临时目录、内存 SQLite 和假网关；不调用真实文本、图片或视频供应商。
- 对照文档更新 `skill-runtime-matrix.md`、`master-checklist.md`，明确本批次关闭的是
  文件管理/可靠重扫，按需激活与阶段归属仍保持缺失。
