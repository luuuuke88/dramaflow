# 任务中心对照：历史、筛选与失败信息

状态：2026-07-19 源码对照 + Flutter widget 回归。本文只覆盖当前路由实际挂载的
`Toonflow-web/src/views/task/index.vue`；`views/taskList/index.vue` 没有注册到路由，
因此是遗留页面，不纳入 1:1 用户行为。

## 结论先行

任务行的展示、类型和状态筛选、失败原因、只读详情，以及移动端项目切换都已经有
可靠实现和回归证据。DramaFlow 还额外提供取消和失败后重试。

不过历史列表**还不能标为完整等价**：原版有“全部项目”选项和服务器分页；
DramaFlow 的历史区始终选定一个项目，并只读取该项目最近 50 条。任务量增长后，
旧记录和其他项目记录无法从当前页面查看，类型/状态筛选也只对这 50 条生效。

这不是外观差异，而是任务追溯范围和性能边界的行为差异，所以总清单已据此下调。

## 用户动作逐项对照

| 用户动作 | ToonFlow 当前行为 | DramaFlow 当前行为 | 判定 |
| --- | --- | --- | --- |
| 浏览历史任务 | 按 ID 倒序，服务器分页，任意项目范围可读 | 当前项目最近 50 条；进行中任务另列在顶部 | 部分实现 |
| 按项目筛选 | 下拉含“全部”，可选具体项目 | 只能选择具体项目；默认第一项目，无“全部项目” | 缺失 |
| 按类型/状态筛选 | 对服务器返回的完整分页结果过滤 | 对当前项目已载入的最近 50 条客户端过滤 | 部分实现 |
| 翻页与每页大小 | 可翻页，页大小可调，返回 `total` | 无分页或“加载更多” | 缺失 |
| 手动刷新 | 顶部明确“刷新”按钮 | 下拉刷新会重读数据；桌面没有对应显式命令 | 部分实现 |
| 查看失败原因 | 失败状态悬停展示原因，表格中也有原因列 | 状态 chip 提示原因，点击行可看详情 | 已验证等价 |
| 查看完整详情 | 后端按任务 ID 读取后展示 | 使用已载入 `TasksRow` 展示类型、状态、描述、模型、关联对象、原因和时间 | 已验证等价 |
| 取消/重试 | 原版任务页没有该动作 | 进行中可取消，失败任务可重试且防重复创建 | DramaFlow 扩展，不计作原版等价 |

## 后续实现边界

未来补齐应先设计一个分页查询接口：项目可空表示全部项目，类型/状态在 SQL 过滤，
返回 `items + total + next page`。移动端可使用“加载更多”，桌面可用分页控件；两端
必须共享同一个查询模型，不能继续把无限历史加载到内存再过滤。
