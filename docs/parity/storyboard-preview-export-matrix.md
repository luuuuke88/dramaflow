# 分镜整体预览与导出对照

这份记录只核对制作画布分镜节点的“预览全部”和“导出/下载”两个动作。它不把逐镜查看、
图片流编辑或工作台快速预览混进来，避免“能看见所有图片”被误判成已经复刻原版的整体拼图。

## 结论

**当前为部分实现。** DramaFlow 可以按分镜顺序逐镜查看，也可以把每张已有首帧分别复制到一个
目录；但 ToonFlow 1.1.8 的可观察产物是“一张带连续 `S01…` 角标的拼图”。这张拼图既是页内
预览对象，也是下载的单个 PNG 文件，Flutter 版本目前没有等价物。

对应总清单条目：

- `W6B-NODE-STORYBOARD-002`：制作画布的入口和交互。
- `W7B-SB-EXPORT-001`：拼图渲染与下载产物。

## 原版行为证据

| 动作 | ToonFlow 1.1.8 的实际行为 | 源码证据 |
| --- | --- | --- |
| 触发条件 | 分镜列表非空时显示“网格预览”按钮；执行时再次筛掉没有 `src` 的分镜。没有有效图片会提示用户，不打开查看器。 | `Toonflow-web/src/views/production/node/storyboard.vue:100,202-250` |
| 取图与顺序 | 前端按当前分镜列表的顺序提交所有有图的 ID；后端按提交 ID 顺序重建文件路径。无文件、不可读或没有尺寸的图片会被忽略。 | `storyboard.vue:202-244`；`Toonflow-app/src/routes/production/storyboard/previewImage.ts:15-45` |
| 网格规则 | 每行最多 5 张。每一列取该列图片的最大宽度、每一行取最大高度；白色画布上把原尺寸图片从各格左上角贴入，因此不同画幅不会被拉伸或裁切。 | `previewImage.ts:59-98`；`downPreviewImage.ts:43-82` |
| 角标 | 只对有效图片从 `S01` 连续编号，在左上角放半透明黑底白字标签。缺图不会留一个空格，也不会占一个编号。 | `previewImage.ts:100-124`；`downPreviewImage.ts:84-108` |
| 页内预览 | 预览专用路径先把每张图缩到最大宽 512px，再合成 JPEG data URL；查看器只接收这一张图，可缩放至 10 倍。 | `previewImage.ts:47-57,126-131`；`storyboard.vue:111-118,231-245` |
| 下载 | 下载路径以原始尺寸合成同样的布局，输出一个无损 PNG 附件，文件名由浏览器端生成为 `storyboardImagePreview-<timestamp>.png`。 | `downPreviewImage.ts:110-127`；`storyboard.vue:202-230` |

## Flutter 当前行为

| 动作 | DramaFlow 当前实现 | 对照结论 |
| --- | --- | --- |
| 预览全部 | 将**全部**分镜（含没有首帧的项）传给 `PageView`；一页一镜，缺图显示占位，编号保持原分镜位置。 | 逐镜审阅体验可用，但不是原版的单图总览；缺图与编号语义也不同。 |
| 导出全部 | 只取有文件路径的首帧，按原分镜位置命名 `S01.png`、`S02.png`，复制到用户选择的目录。 | 保存了源文件，但用户得到的是一组散图而不是一个可分享/打印的编号拼图 PNG。 |
| 空态 | 没有可导出首帧时显示本地化提示，不打开文件选择器。 | 此项已有自动化证据，和原版用户结果一致。 |

## 差异边界

| 编号 | 用户可观察差异 | 为什么不能标为等价 |
| --- | --- | --- |
| D1 | 原版预览是一张拼图，Flutter 是可左右翻的多页画廊。 | 用户不能一眼看到镜头间的构图、节奏和数量。 |
| D2 | 原版只显示有效图片且连续编号，Flutter 还显示未生成占位并保留原镜头编号。 | 同一批混合状态分镜会得到不同的可见内容和 `Sxx` 标号。 |
| D3 | 原版下载一个 PNG，Flutter 导出多个原始图片。 | 下载后的文件数量、格式、用途和分享方式不同。 |
| D4 | 原版预览专用缩略图限制单图宽度为 512px，下载保留原尺寸；Flutter 没有合成图，因此没有这两个有意区分的输出。 | 不能以“图片都能看”代替两种产物语义。 |
| D5 | 原版最多五列且以原图尺寸构造不规则网格。 | Flutter 当前没有网格布局或角标渲染路径。 |

## 后续补齐的验收口径

本项后续实现必须先经过独立设计与计划，不在本次审计中改功能。实现后至少要证明：

1. 引擎仅加载可读首帧，顺序来自分镜顺序，跳过缺图后从 `S01` 连续编号。
2. 纯 Dart 合成器使用最多五列、白底、保持比例、左上角半透明编号；预览缩略图与下载 PNG 的尺寸策略分别可测试。
3. 桌面端“预览全部”打开一张可缩放拼图，“导出全部”通过系统保存面板保存一个 PNG，而不是要求选择文件夹。
4. 390dp 端能打开同一拼图并把单个 PNG 交给系统保存/分享路径，按钮和错误信息可达且不溢出。
5. 夹具覆盖不同画幅、缺图、顺序错位、零有效图、五列边界和六张换行；无需调用图像或视频供应商。

视频生成不属于本项的自动化范围，也不会在实现或回归中发起真实 Seedance 请求。
